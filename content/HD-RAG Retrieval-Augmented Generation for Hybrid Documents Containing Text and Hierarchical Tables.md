## 📝 Abstract

### 원문

With the rapid advancement of large language models (LLMs), Retrieval-Augmented Generation (RAG) effectively combines LLMs' generative capabilities with external retrieval-based information. The Hybrid Document RAG task aims to integrate textual and hierarchical tabular data for more comprehensive retrieval and generation in complex scenarios. However, there is no existing dataset specifically designed for this task that includes both text and tabular data. Additionally, existing methods struggle to retrieve relevant tabular data and integrate it with text. Semantic similarity-based retrieval lacks accuracy, while table-specific methods fail to handle complex hierarchical structures effectively. Furthermore, the QA task requires complex reasoning and calculations, further complicating the challenge. In this paper, we propose a new large-scale dataset, DocRAGLib, specifically designed for the question answering (QA) task scenario under Hybrid Document RAG. To tackle these challenges, we introduce HD-RAG, a novel framework that incorporates a row-and-column level (RCL) table representation, employs a two-stage process combining ensemble and LLM-based retrieval, and integrates RECAP, which is designed for multi-step reasoning and complex calculations in Document-QA tasks. We conduct comprehensive experiments with DocRAGLib, showing that HD-RAG outperforms existing baselines in both retrieval accuracy and QA performance, demonstrating its effectiveness.

### 번역

대형 언어 모델(LLM)의 급속한 발전과 함께, 검색 증강 생성(RAG)은 LLM의 생성 능력과 외부 검색 기반 정보를 효과적으로 결합합니다. 하이브리드 문서 RAG 작업은 복잡한 시나리오에서 보다 포괄적인 검색 및 생성을 위해 텍스트와 계층적 표 데이터를 통합하는 것을 목표로 합니다. 그러나 텍스트와 표 데이터를 모두 포함하는 이 작업을 위해 특별히 설계된 기존 데이터셋은 없습니다. 또한 기존 방법들은 관련 표 데이터를 검색하고 이를 텍스트와 통합하는 데 어려움을 겪습니다. 의미 유사성 기반 검색은 정확성이 부족하고, 표 전용 방법들은 복잡한 계층 구조를 효과적으로 처리하지 못합니다. 게다가 질의응답 작업은 복잡한 추론과 계산을 요구하여 문제를 더욱 복잡하게 만듭니다. 본 논문에서는 하이브리드 문서 RAG 하에서 질의응답(QA) 작업 시나리오를 위해 특별히 설계된 새로운 대규모 데이터셋인 DocRAGLib을 제안합니다. 이러한 문제를 해결하기 위해, 행-열 수준(RCL) 표 표현을 통합하고, 앙상블과 LLM 기반 검색을 결합한 2단계 프로세스를 사용하며, 문서 QA 작업에서 다단계 추론과 복잡한 계산을 위해 설계된 RECAP을 통합하는 새로운 프레임워크인 HD-RAG를 소개합니다. DocRAGLib을 사용한 포괄적인 실험을 수행한 결과, HD-RAG가 검색 정확도와 QA 성능 모두에서 기존 기준선을 능가하며 그 효과성을 입증했습니다.

## 🔍 해결하고자 하는 문제

### 현실의 복잡성

실제 문서 저장소는 수천 개의 유사한 문서를 포함하며, 각 문서는 텍스트와 복잡한 계층적 테이블을 함께 담고 있습니다. 예를 들어:
- **캐나다 통계청**: 노동 분야 1,761개, 인구통계 1,132개 보고서
- 의미적으로 유사하면서도 복잡한 테이블 구조 포함

### 기존 접근법의 한계

#### 1️⃣ 텍스트 중심 RAG의 한계
- 텍스트 검색에는 효과적이지만 **테이블 정보 포착 실패**
- 의미 유사성만으로는 실제 필요한 증거를 찾지 못함
- 예: "2014년" 언급 문서 검색 → 실제 필요한 2012-2013 데이터 놓침

#### 2️⃣ 테이블 중심 RAG의 한계
- 테이블-텍스트 **통합 부족**
- 복잡한 계층 구조 처리 시 **정보 손실**
- 계층적 헤더 간 관계와 종속성 표현 실패

#### 3️⃣ 복잡한 추론의 어려움
- 텍스트와 테이블을 넘나드는 **다단계 추론** 필요
- 증가율 계산 → 미래 값 예측 등 **복잡한 수학적 계산** 요구
- 기존 LLM의 수치 계산 불안정성

## 🏗️ HD-RAG 프레임워크 구조

### 1. 📚 코퍼스 구축 모듈 (Corpus Construction Module)

#### H-RCL (Hierarchical Row-and-Column Level) 테이블 표현

**기존 방법의 문제점:**
- 테이블 전체를 단순 요약 → 핵심 정보 손실
- 구조적 세부사항 무시

**H-RCL의 핵심 아이디어:**
```
계층적 테이블 T = {Hₜ, Hₗ, d}
- Hₜ: 상위(top) 헤더의 계층 구조
- Hₗ: 좌측(left) 헤더의 계층 구조  
- d: 데이터 셀

경로 정의:
Pₗ(i) = h¹ₗ(i₁) → h²ₗ(i₂) → ... → hᴷₗₗ(iₖₗ)
Pₜ(j) = h¹ₜ(j₁) → h²ₜ(j₂) → ... → hᴷₜₜ(jₖₜ)
```

**동작 방식:**
1. 각 행과 열을 계층적 경로를 따라 요약
2. 다층 구조와 셀 간 종속성 보존
3. LLM에 제공하여 최종 요약 생성

**예시:**
```
"Revenues → Electric sales to affiliates" 행은 
2013년 $652M, 2012년 $515M을 기록
→ 계층 구조와 데이터를 모두 포함한 요약
```

### 2. 🔎 검색 모듈 (Retrieval Module)

#### 2단계 검색 전략

**🔹 1단계: 앙상블 검색 (재현율 우선)**

**BM25 검색:**
- 키워드 매칭 강조
- "Total Buy" 같은 정확한 용어 포착
- 테이블 수준 코퍼스 사용 (키워드 반복 문제 완화)

**임베딩 기반 검색:**
- 의미적 유사성 계산
- text-embedding-3-large 모델 사용
- H-RCL 코퍼스 사용 (구조 정보 보존)

**후보 병합:**
```
BM25 상위 n개 + 임베딩 상위 m개 
→ 중복 제거 → 최종 상위 k개 후보
```

**🔹 2단계: LLM 기반 검색 (정밀도 우선)**

**문제 인식:**
- 각 문서가 길어 모두 입력 시 토큰 제한 초과
- 관련 없는 정보가 LLM 정확도 감소

**해결 방법:**
1. 필터링 임계값 Θ 설정
2. 각 문서에서 질문과 가장 유사한 상위 Θ개 청크 선택
3. 선택된 청크로 "새 문서" D'ᵢ 재구성
4. LLM에 질문 + 상위 k개 새 문서 입력
5. 최종 관련 문서 D* 선택

### 3. 💡 QA 추론 모듈 (QA Inference Module)

#### RECAP 전략 (Restate, Extract, Compute, Answer, Present)

**5단계 추론 프로세스:**

```
1. Restate (재진술)
   → 질문 내용과 유형 명확화

2. Extract (추출)
   → 문서에서 관련 데이터 추출

3. Compute (계산)
   → 단계별 계산/추론 수행

4. Answer (답변)
   → 고정 형식으로 답변 제공

5. Present (제시)
   → 계산 공식 명시
```

**예시 (논문 Figure 1):**
```
질문: "이전 연도 증가율이 계속되면, 2014년 
      Total Buy + Electric Sales 합은?"

1. Restate: 
   "2013/2012 증가율 계산 → 2013년 값에 적용 → 합산"

2. Extract:
   "Total Buy: 2013=$11.2M, 2012=$10.9M
    Electric Sales: 2013=$652M, 2012=$515M"

3. Compute:
   "Total Buy 증가율 = (11.2-10.9)/10.9
    2014 예상 = 11.2 × (1 + 증가율)
    Electric Sales도 동일 계산"

4. Answer: "836.45"

5. Present: 
   "11.2×(1+(11.2-10.9)/10.9) + 652×(1+(652-515)/515)"
```

**이중 검증:**
- LLM → 1~4단계 수행 → 답변 A₁
- 계산기 → 5단계 공식 실행 → 답변 A₂
- 규칙 기반으로 더 신뢰할 수 있는 답 선택

## 🔬 기술적 세부사항

### H-RCL 표현 메커니즘

**계층 구조 보존:**
```
예: 재무 보고서 테이블

최상위: "Revenues"
  ├─ "Electric Sales"
  │   ├─ 2013: $652M
  │   └─ 2012: $515M
  └─ "Other"
      ├─ 2013: $6M
      └─ 2012: $16M

경로 표현:
Pₗ = "Revenues → Electric sales to affiliates"
Pₜ = "2013"
→ 셀 값: $652M
```

**요약 생성:**
```
행 요약 Sᵣₒw:
"Revenues → Electric sales to affiliates 행은 
 2013년에 $652M, 2012년에 $515M을 기록"

열 요약 Sᶜₒₗ:
"2013년 열은 Electric Sales $652M, 
 Other $6M을 포함"

최종 요약 Sₜₐᵦₗₑ = Sᵣₒw ∪ Sᶜₒₗ
```

### 2단계 검색 작동 원리

**1단계: 앙상블 검색**
```python
# BM25 검색 (테이블 수준 코퍼스)
bm25_candidates = BM25.retrieve(query, n=5)

# 임베딩 검색 (H-RCL 코퍼스)
embedding_candidates = Embedding.retrieve(query, m=5)

# 병합 (중복 제거)
top_k = merge_deduplicate(bm25_candidates, embedding_candidates)
# → k=10개 후보
```

**2단계: LLM 검색**
```python
# 각 문서에서 상위 Θ개 청크 선택
for doc in top_k:
    relevant_chunks = select_top_chunks(query, doc, Θ=20)
    new_doc = reconstruct(relevant_chunks)

# LLM으로 최종 문서 선택
final_doc = LLM.select_most_relevant(query, new_docs)
```

### RECAP 추론 예시

**질문:** "2014년 Total Buy + Electric Sales 합은?"

```
📝 1. Restate
분석: 2013년 대비 2012년 증가율 → 2013년에 적용 → 합산
유형: 수치 계산 + 추세 예측

📊 2. Extract
- Total Buy 2013: $11.2M
- Total Buy 2012: $10.9M  
- Electric Sales 2013: $652M
- Electric Sales 2012: $515M

🧮 3. Compute
Total Buy 증가율 = (11.2 - 10.9) / 10.9 = 0.0275
2014 Total Buy = 11.2 × (1 + 0.0275) = 11.508

Electric Sales 증가율 = (652 - 515) / 515 = 0.266
2014 Electric Sales = 652 × (1 + 0.266) = 825.432

합계 = 11.508 + 825.432 = 836.94

✅ 4. Answer
836.45 (정답과 일치)

📐 5. Present
11.2 × (1 + (11.2-10.9)/10.9) + 652 × (1 + (652-515)/515)

계산기 실행 → 836.45 ✓
```

```
- 사회 안전망 강화
```

## 📌 최종 요약

**HD-RAG 연구는** 텍스트와 계층적 테이블이 혼재된 하이브리드 문서를 위한 검색 증강 생성 프레임워크로, 최초의 전용 데이터셋 DocRAGLib(2,178개 문서, 4,468개 QA 쌍)을 구축하고, 계층적 행-열 수준(H-RCL) 테이블 표현과 앙상블-LLM 2단계 검색, 그리고 다단계 추론 및 외부 계산을 통합한 RECAP 방법을 제안하여 **기존 방법 대비 검색에서 40% 이상, QA에서도 상당한 성능 향상**을 달성했습니다.

## 📚 후속 작업 제안

1️⃣ **DocRAGLib 데이터셋의 상세 분석** - 데이터셋의 구성, 난이도 분포, 질문 유형별 특성을 심층 분석하여 하이브리드 문서 QA의 본질적 어려움을 파악합니다.

2️⃣ **H-RCL 표현의 변형 실험** - 행-열 수준 외에 셀 수준, 블록 수준 등 다양한 세분화 수준에서의 테이블 표현을 비교하고, 최적의 균형점을 찾습니다.

4️⃣ **계산 효율성 개선 방안 연구** - 소형 LLM이나 특화 모델을 사용한 경량화 버전, 캐싱 전략, 계층적 검색 등을 통해 실시간 응용에 적합하도록 최적화합니다.

5️⃣ **RECAP 방법의 다른 복잡한 추론 작업으로의 적용** - 과학적 추론, 수학 문제 해결, 다단계 계획 수립 등 다른 복잡한 추론 작업에 RECAP을 적용하여 범용성을 검증합니다.
