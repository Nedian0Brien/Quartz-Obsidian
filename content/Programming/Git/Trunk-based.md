
안정적인 운영보다는 빠른 개발과 빠른 배포가 필요할 때 사용

코드 짠걸 바로 배포해도 상관없다면 굳이 많은 브랜치를 사용하지 않고  그냥 main 브랜치와 feature 브랜치만 운영

![[Pasted image 20231001233550.png]]

1. 기능 추가, 버그 픽스가 필요하면 main 브랜치에서 새로운 브랜치를 하나 만들어서 코드 짜기
	- 브랜치마다 작명 잘하는게 중요
2. 기능이 완성되었으면 main 브랜치에 합침
	- 이제 브랜치 필요없으니 삭제
3. main 브랜치에 있는 코드를 필요할때마다 유저들에게 배포

#### 장점
1. 코드를 한 브랜치에서만 관리하기 때문에 편리하다
2. 크게 개발해서 한번에 merge 하는 것보다 작은 단위로 merge하는 것이 더 안전하다

#### 단점
1. main 브랜치에 있는 코드에 문제가 있으면 큰 문제가 될 수 있기 때문에 테스트나 코드리뷰를 자주 해야 한다.

> 이미 어느정도 개발이 진척이 되었거나 프로 코딩전사(...)로 가득한 팀이면 git-flow보다 trunk-based 쓰는게 훨씬 편리함

CI/CD와 같은 방식으로 개발하는 팀들도 trunk-based 개발 방식을 적용
